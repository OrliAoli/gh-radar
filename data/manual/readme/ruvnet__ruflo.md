# Ruflo

**一个给 Claude Code 和 Codex 用的「Agent 元调度框架」。**

[![RuFlo Explained —— 搭一支会规划、会记忆、会测试、会自我改进的 AI 团队](docs/assets/ruflo-explained/ch14.jpg)](docs/ruflo-explained.md)

**［📖 RuFlo 详解 —— 搭一支会规划、会记忆、会测试、会自我改进的 AI 团队］（[docs/ruflo-explained.md](docs/ruflo-explained.md)）**
共 14 章：从最基础的概念讲起，到跑通第一个有用的任务，再到记忆、Agent 团队、插件、成本和校验。

</div>

> **Agent = 模型 + 调度框架。** 模型负责「写」，调度框架负责给它工具、记忆、循环、沙箱和控制手段，让它真的能干活。**Ruflo 就是那个调度框架**——它是包在 Claude Code 和 Codex 外面的一层执行层，额外提供了 100 多个专业 Agent、协同编队、自我学习型记忆、跨机器联邦通信，以及企业级安全护栏。让 Agent 不只「能跑」，还能「互相配合」。
>
> 只要一句 `npx ruflo init`，就能给 Claude Code 装上一套神经系统：Agent 自动结成编队、从每次任务里学习、跨会话记住上下文，开了联邦之后还能跟别的机器上的 Agent 安全对话而不泄露数据。你照旧写代码，协同的事情 Ruflo 来管。

```
自我学习 / 自我优化的 Agent 架构

用户 --> Ruflo (CLI/MCP) --> 路由器 --> 编队 --> Agent --> 记忆 --> 大模型供应商
                          ^                           |
                          +---- 学习闭环 <------------+
```

> **刚接触 Ruflo？** 你不需要去背 314 个 MCP 工具或 26 条 CLI 命令。`init` 之后照常用 Claude Code 就行——钩子（hooks）系统会自动分派任务、从成功的模式里学习、在后台协调 Agent。

## 快速开始

这里有**两条完全不同的安装路线**，暴露出来的能力差别很大。按你的需要挑（[#1744](https://github.com/ruvnet/ruflo/issues/1744)）：

| | **Claude Code 插件** | **CLI 安装（`npx ruflo init`）** |
|---|---|---|
| 你能得到什么 | 斜杠命令 + 少量技能 + 各插件自带的 Agent 定义 | 完整的 Ruflo 闭环——98 个 Agent、60+ 条命令、30 个技能、MCP 服务、钩子、守护进程 |
| 在工作目录里留下多少文件 | **零** | `.claude/`、`.claude-flow/`、`CLAUDE.md`、辅助脚本、配置文件 |
| 是否会注册 MCP 服务 | 只有装了 `ruflo-core` 才会（它自带 `.mcp.json`），其他插件基本不注册 | 是 |
| 是否安装钩子 | 否 | 是 |
| 适合什么人 | 只想试用某个插件的命令，不想全量安装 | 生产环境使用——所有功能都按文档正常工作 |

### 路线 A —— Claude Code 插件（轻量版，只有斜杠命令）

```bash
# 添加插件市场
/plugin marketplace add ruvnet/ruflo

# 安装核心插件 + 你需要的插件
/plugin install ruflo-core@ruflo
/plugin install ruflo-swarm@ruflo
/plugin install ruflo-rag-memory@ruflo
/plugin install ruflo-neural-trader@ruflo
```

这会加入斜杠命令和 Agent 定义。上面装好的 `ruflo-core` **确实**会在安装时注册自己的 MCP 服务，它的工具要这么调用：`mcp__plugin_ruflo-core_ruflo__*`（比如 `mcp__plugin_ruflo-core_ruflo__memory_store`），而不是 CLI 路线那套裸名字（`memory_store` / `swarm_init` / `agent_spawn`）。其他插件一般不带自己的 MCP 服务。想用 CLI 那套完整闭环和工具名，走下面的路线 B。

### CLI 安装

**macOS / Linux / WSL / Git-Bash：**

```bash
# 一行安装（仅 POSIX shell —— Windows 用户看下面）
curl -fsSL https://cdn.jsdelivr.net/gh/ruvnet/ruflo@main/scripts/install.sh | bash
```

**全平台（含原生 Windows PowerShell / cmd）：**

```bash
# 交互式安装向导 —— 各平台表现一致
npx ruflo@latest init wizard

# 快速非交互式初始化
# npx ruflo@latest init

# 或者全局安装
npm install -g ruflo@latest
```

> 💡 **Windows 用户：** `curl ... | bash` 这种写法需要 POSIX shell（Git-Bash、WSL、MSYS）。`npx ruflo@latest init wizard` 这行在 PowerShell 和 cmd 里原生可用。如果你遇到 `'bash' is not recognized` 的报错，改用 `npx` 那行——两条走的是同一套初始化流程。

### MCP 服务

```bash
# 把 Ruflo 作为 MCP 服务加到 Claude Code 里
claude mcp add claude-flow -- npx ruflo@latest mcp start
```

### Web UI（Beta）—— 可自托管，托管版在 [flo.ruv.io](https://flo.ruv.io/)

|---|------------|----------------|

### 目标规划器界面 —— 自主 Agent，在 [goal.ruv.io](https://goal.ruv.io/)

**把高层目标变成可执行的 Agent 计划。** `goal.ruv.io` 是 RuFlo 托管的目标导向行动规划（GOAP）前端——用大白话描述一个结果，看着 RuFlo 把它拆成前置条件、动作，以及在状态空间里的一条 A\* 路径，然后把活派给 [`/agents`](https://goal.ruv.io/agents) 上的在线 Agent。

| | 是什么 | 为什么重要 |
|---|------------|----------------|
| 🎯 | **大白话写目标** | 输入「把 auth 重构做完，带上测试并提 PR」——RuFlo 会自己提炼出成功标准、约束条件和隐含的前置条件。不需要写 JSON，也不需要学什么领域专用语言。 |
| 🧭 | **GOAP A\* 规划器** | 把游戏 AI 里的经典规划搬到了软件工程上：在带前置条件和效果的动作空间里做状态搜索，找出最短的可行路径。状态变了还能随时重新规划。 |
| 🤖 | **实时 Agent 面板** | [goal.ruv.io/agents](https://goal.ruv.io/agents) 显示每一个被拉起来的 Agent——角色、当前步骤、记忆命名空间、token 预算、状态。点进去能查看执行轨迹、杀掉失控的工作器，或者重新分派。 |
| 🌳 | **可视化计划树** | 目标渲染成可折叠的动作树，进度、被阻塞的分支和回滚都会高亮。你能看到 Agent **为什么**选了这条路——不是一团黑盒的思维链。 |
| ♻️ | **自适应重规划** | 某个动作失败或来了新信息时，规划器会从当前状态重新跑 A\*，而不是从头重来。失败变成学习素材，不变成死循环。 |
| 🧠 | **共享记忆 + SONA** | 计划、轨迹和结果都流进 AgentDB。以后做计划时通过 HNSW 检索过往解法——规划器每跑一次就更聪明一点。 |
| 🔗 | **接上 MCP 工具** | 每个动作节点都对应一次工具调用（RuFlo 那约 210 个 MCP 工具、你自定义的服务器，或者 shell）。在依赖图允许的地方，规划器会并行调度。 |
| 🚀 | **零安装就能试** | 打开 [goal.ruv.io](https://goal.ruv.io/)，描述一个目标，看着它跑。源码在 [`v3/goal_ui/`](v3/goal_ui/) —— Vite + Supabase，可自托管。 |

**试一下：** [https://goal.ruv.io/](https://goal.ruv.io/) 看目标规划 · [https://goal.ruv.io/agents](https://goal.ruv.io/agents) 看在线 Agent。**自己跑：** 克隆 `goal` 分支，然后 `cd v3/goal_ui && npm install && npm run dev`。

### Agent 联邦 —— 给 Agent 用的 Slack

```
你的 Agent --> [ 去掉敏感信息 ] --> [ 消息签名 ] --> [ 加密通道 ]
                 邮箱、身份证号、        证明这条消息        中途没人看得见
                 密钥都被剥掉             确实来自你
                                                                |
                                                                v
对方的 Agent <-- [ 拦截攻击 ] <-- [ 校验身份 ] <----------------+
                 挡住提示词注入      伪造的直接拒掉

                          两边都留审计记录。
                  信任随时间累积。一旦行为不端，立刻降级。
```

Slack 给了团队「频道」，联邦给 Agent 同样的东西——**跨信任边界的共享工作空间**：不同机器、不同组织、不同云区域上的 Agent 可以互相发现对方、证明自己是谁，然后一起做任务。

区别在于：有的频道可信，有的不可信。[`@claude-flow/plugin-agent-federation`](https://github.com/ruvnet/ruflo/issues/1669) 会自动处理这件事。你的 Agent 加入联邦，通过 mTLS + ed25519 完成验证，然后开始交换任务——任何东西离开你的节点之前，个人敏感信息会先被剥掉，每条消息都可审计。不受信的 Agent 仍然可以参与，只是权限更低：它们能看到发现信息，看不到你的记忆。等它们证明了自己可靠，信任等级会升上去。如果行为不端，立刻被降级——不需要人介入。

你不用配握手协议，也不用管证书。你只要 `federation init`、`federation join`，Agent 就开始对话了。协议管身份，PII 流水线管数据安全，审计记录管合规。

> **📘 完整用户指南：** [`docs/federation/`](./docs/federation/) —— 安装、MCP 工具、信任等级、熔断机制，以及（可选的）把网络层可达性和联邦信任绑定起来的 WireGuard 网格层。ADR-111 深度解析见 [`docs/federation/phase7-mesh-bringup.md`](./docs/federation/phase7-mesh-bringup.md)。

<details>
<summary><strong>联邦的能力</strong></summary>

| | 能力 | 怎么实现的 |
|---|---|---|
| 🔒 | **零信任联邦** | 远端 Agent 一开始都是不受信的。身份通过 mTLS + ed25519 挑战-响应来证明。不用 API Key，不用共享密钥。 |
| 🛡️ | **PII 把关的数据流** | 14 类检测流水线扫描每一条外发消息。按信任等级执行不同策略：BLOCK（拦截）、REDACT（脱敏）、HASH（哈希）或 PASS（放行）。自适应校准会降低误报。 |
| 📊 | **行为信任打分** | 公式（`0.4×成功率 + 0.2×在线率 + 0.2×威胁度 + 0.2×完整性`）持续评估对端。升级需要历史表现，降级是立刻生效。 |
| 📋 | **合规内建** | HIPAA、SOC2、GDPR 审计记录作为合规模式提供。每个联邦事件都产生一条结构化记录，可以通过 HNSW 检索。 |
| 🤝 | **9 个 MCP 工具 + 10 条 CLI 命令** | 覆盖完整生命周期：`federation_init`、`federation_send`、`federation_trust`、`federation_audit` 等等。 |

</details>

<details>
<summary><strong>例子：两个团队共享欺诈信号，但不共享客户数据</strong></summary>

```bash
# A 队：初始化联邦并生成密钥对
npx claude-flow@latest federation init

# A 队：加入 B 队的联邦端点
npx claude-flow@latest federation join wss://team-b.example.com:8443

# A 队：发送任务 —— 个人敏感信息在离开本机前会自动被剥掉
npx claude-flow@latest federation send --to team-b --type task-request \
  --message "Analyze transaction patterns for account anomalies"

# A 队：查看对端信任等级和会话健康度
npx claude-flow@latest federation status
```

</details>
